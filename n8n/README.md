# ИИ-гид: что нужно сделать один раз

Гид в приложении уже готов и ждёт ответа от сервера. Ключа модели
в приложении нет и не будет — он живёт на сервере n8n, как в NEXUS.

Пока воркфлоу не заведён, гид честно пишет «пока недоступен» и ничем
не мешает: приложение работает целиком без него.

## Три шага

**1. Импортировать воркфлоу.**
В n8n: `Workflows → Import from File →` выбрать `n8n/atlas-guide.json`.

**2. Дать ему ключ.**
Воркфлоу берёт ключ из переменной окружения `GEMINI_API_KEY` — той же,
что уже используют другие воркфлоу. Если её нет, завести в настройках n8n
(бесплатный ключ Gemini берётся на `aistudio.google.com`).

**3. Включить.**
Переключатель `Active` в правом верхнем углу. Адрес получится такой:

```
https://178-105-123-85.nip.io/webhook/atlas/v1/guide
```

Он уже прописан в приложении (`src/lib/guide.ts`). Менять ничего не надо.

## Как проверить, что работает

```bash
curl -s -X POST https://178-105-123-85.nip.io/webhook/atlas/v1/guide \
  -H "Content-Type: application/json" \
  -d '{"app":"atlas","intent":"explain","lang":"ru","subject":"Древний Рим","material":"Древний Рим — цивилизация, существовавшая с 753 года до нашей эры до 476 года."}'
```

Должен вернуться JSON с полями `app: "atlas"` и `answer`.

## Почему подпись `app: "atlas"` обязательна

На NEXUS однажды адрес указывал на воркфлоу **другого** приложения,
и «наставник по коду» бодро учил инвестициям. Заметили это только глазами.

Теперь воркфлоу подписывает каждый ответ, а приложение отказывается
показывать неподписанный. Если однажды адрес уедет не туда, человек
увидит «гид отвечает не отсюда», а не чужие слова под видом своих.

## Что гиду разрешено

Отвечать **только по тексту, который человек уже открыл**. В задании модели
это записано трижды, включая прямой запрет называть даты и имена, которых
в тексте нет. Причина простая: даты в приложении проверены по Wikidata,
а придуманные моделью — нет, и отличить их человек не сможет.
